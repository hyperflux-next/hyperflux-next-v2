Razer HyperFlux V2 on Linux.

OpenRazer, Polychromatic and OpenRGB control the devices paired to it.

One line

$ curl -fsSL https://hyperflux-next.github.io/hyperflux-next-v2/install.sh | sh

Read it first

$ curl -fsSLO https://hyperflux-next.github.io/hyperflux-next-v2/install.sh
$ less install.sh
$ sh install.sh

Your package manager asks before it installs, and the script asks before it reboots. Version 1.0.6, x86_64.

Install guides

Where they show up

Typing and pointing don't go through it, so they work as they always have.

  • OpenRazerLighting and battery, in Polychromatic and other OpenRazer apps.
  • OpenRGBLighting through a plugin, for OpenRGB 1.1 (and Debian's 1.0).
  • Battery widgetCharge level, and whether it's charging.
  • hyperfluxctlstatus, devices, battery and doctor in a terminal.

Install

Packages for x86_64, signed by the project. A distribution based on one of these releases can use them too, if it runs systemd.

  1. Plug in the receiver

    Before you start.

    $ lsusb | grep 1532:00cf
Bus 003 Device 002: ID 1532:00cf Razer USA, Ltd Razer HyperFlux V2

  2. Run the one line, or follow a guide

    Both add the package repository and install hyperflux-next-v2-full. On Ubuntu and Fedora the OpenRGB plugin is a separate package. openSUSE has none.

    • Arch Linuxguide
    • Ubuntu 26.10, Debian 14guide
    • Fedora 44 and 45, openSUSE Tumbleweedguide

  3. Ask doctor

    After the reboot, hyperfluxctl doctor prints HyperFlux Next V2 is ready. When something is missing it names it, with the fix:

    $ hyperfluxctl doctor
HyperFlux Next V2 needs attention.
Primary issue: [HFX-401] The OpenRazer driver from HyperFlux Next V2 isn't active yet.
Do: Reboot. If Doctor still reports it, reinstall hyperflux-next-v2-openrazer-driver-dkms.
